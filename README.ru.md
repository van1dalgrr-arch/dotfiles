## Зачем

У меня 8 ГБ памяти, и при этом одновременно работают Docker, Go и пара редакторов. Поэтому всё здесь
построено вокруг двух целей: **ничего не должно тормозить** и **должно выглядеть красиво**.

- **Docker — на OrbStack**, а не Docker Desktop. Память берётся, когда нужна, и отдаётся обратно, а не висит виртуалкой на 4 ГБ весь день.
- **Промпт — чистый zsh**, без starship. Вне git-репозитория он не запускает ни одного процесса, внутри — один `git status`. Оболочка стартует за ~0.15 с.
- **Zed вместо VS Code** для повседневного кода — обычно в разы меньше памяти.
- **Обои не работают в фоне** — это обычные динамические HEIC, кадры переключает сама macOS.
- **Всё проверяется, а не предполагается.** `dot doctor` за ~2 с проверяет всю настройку и к каждой проблеме пишет, как её починить.

> Комментарии в конфигах и сообщения команд — на русском, это мой родной язык.

## Кто пишет код

**Почти весь код здесь пишет нейросеть — [Claude](https://claude.com/claude-code) (Anthropic) в Claude Code.**
Я ставлю задачи, решаю, что оставить, проверяю на своём маке и говорю, что не так. Иногда — прямо с телефона,
пока ноутбук лежит закрытым (поэтому есть `awake`).

Как это устроено на практике:

- **Каждый коммит, написанный нейросетью, подписан** строкой `Co-Authored-By: Claude` — по `git log` видно, что сделано так.
  Скрывать это смысла нет: читающему код полезно знать, откуда он.
- **Нейросеть не верят на слово — её проверяют.** Всё, что можно проверить автоматически, проверяется: `make check`
  (shellcheck, синтаксис bash 3.2 и zsh, шейдеры, Go-тесты, gitleaks), `make test` (установка и удаление во временном HOME),
  CI на каждый push и `dot doctor` на живой системе. Если что-то проверить нельзя, это пишется прямо.
- **Решения — мои, исполнение — её.** Что ставить, что убрать, как должно выглядеть — решаю я; нейросеть предлагает,
  объясняет компромиссы и делает. Отвергнутое откатывается без сожалений (так ушли нарисованные кодом обои-сцены).
- **Комментарии в коде и документация — тоже от нейросети**, на русском и английском.

Если берёшь что-то себе — читай перед запуском, как любой чужой код. Скрипты показывают план и ничего не меняют без `--yes`.

## Установка

**Что нужно:** macOS на Apple Silicon (собрано на Tahoe; пути рассчитаны на `/opt/homebrew`), учётная запись администратора, интернет.

```bash
curl -fsSL https://raw.githubusercontent.com/van1dalgrr-arch/dotfiles/main/bootstrap.sh | bash
```

Ставит Command Line Tools и Homebrew, клонирует репозиторий в `~/dotfiles` и запускает `make install`.
Всё, что уже есть, пропускается, поэтому запускать повторно безопасно. `bootstrap.sh --dry-run` покажет план.

Потом:

```bash
exec zsh                 # новая оболочка со всем загруженным
./macos.sh               # план системных настроек → ./macos.sh --yes, чтобы применить
dot doctor               # всё должно быть ✓
```

<details>
<summary><b>Вручную — и что делает <code>install.sh</code></b></summary>

`xcode-select --install` → [Homebrew](https://brew.sh) → `git clone … ~/dotfiles` → `make install`.

`./install.sh` можно запускать сколько угодно раз. Он:

- делает симлинки на все конфиги (файл, который уже лежит на месте, сохраняется как `*.bak`, ничего не удаляется)
- клонирует oh-my-zsh и fzf-tab на **закреплённых коммитах**, без установщика oh-my-zsh, который перезаписал бы `.zshrc`
- ставит Go-утилиты **закреплённых версий** из `go/tools.txt`
- собирает `orbstack` из `berth/` в `~/go/bin`
- применяет тему и обои

Программы он не ставит (это `brew bundle`) и настройки macOS не трогает (это `macos.sh`).
Необязательное: `make devops` (инструменты Kubernetes / IaC) и `./macos.sh` (системные настройки).

</details>

**Удаление:** `./uninstall.sh` показывает план. `./uninstall.sh --yes` убирает симлинки и возвращает
твои `*.bak`, а `--purge` ещё и удаляет сгенерированные файлы темы. Пакеты Homebrew остаются.

### Взять себе

Лучше форкнуть, чем ставить мою настройку как есть. Перед `make install`:

1. **Имя в git:** поменяй `name` и `email` в [`git/.gitconfig`](git/.gitconfig) — иначе твои коммиты будут подписаны мной.
2. **Программы:** оставь в [`Brewfile`](Brewfile) только то, чем пользуешься (`dot doctor --deep` потом покажет всё, что стоит мимо него).
3. **Настройки macOS:** прочитай [`macos.sh`](macos.sh) — каждая настройка в одну строку с описанием; одна группа — `./macos.sh --yes <группа>`.

## Каждый день

Забыл команду? Нажми `?` (или `ctrl+/`) — откроется шпаргалка со всеми хоткеями, функциями и алиасами.

| Команда | Что делает |
|---|---|
| `p` | перейти в проект из `~/dev` (fzf с превью и последними коммитами) |
| `up` | поднять только зависимости из compose (postgres, redis…) и запустить приложение с `.env` |
| `pl` | все проекты разом: стек, ветка, незакоммиченное, давность последнего коммита |
| `nvim .` | Neovim на LazyVim в папке проекта (`пробел` — меню всех действий) |
| `gonew myapi` | новый проект на Gin с air и git |
| `got` / `gotw` | тесты через gotestsum / заново при каждом сохранении |
| `pd` | `dot project doctor`: что в текущем проекте есть и чего не хватает |
| `db` | pgcli к базе проекта (из `DATABASE_URL` / `.env`) |
| `vuln` | уязвимости: govulncheck для Go-зависимостей + trivy для остального |
| `load` | нагрузочный тест через oha (по умолчанию `/health`) |
| `orbstack` | контейнеры: живая панель, шаблоны, логи, внутренности, живая сборка ([подробнее](#контейнеры-orbstack)) |
| `dsh` / `dlogs` | зайти в контейнер / смотреть его логи (выбор через fzf) |
| `gco` | переключить ветку через fzf |
| `killport 8080` | освободить порт (сначала TERM, через 2 с — KILL) |
| `ram` | что ест память — по приложениям, а не по процессам |
| `lean` | память на 8 ГБ: отчёт · `lean on` закрывает тяжёлое из списка · `lean off` возвращает |
| `awake on` / `off` | не засыпать с закрытой крышкой (для Claude Code с телефона); `dot doctor` напомнит, если забыл выключить |
| `update` | обслуживание раз в неделю: brew, закреплённые Go-утилиты, мусор Docker, tldr, иконки, пересборка `orbstack` |
| `work kinoza-back` / `work off` | режим проекта: OrbStack, его контейнеры и Zed одной командой, в промпте `◆ имя 1ч12м`; `off` гасит всё ([`work/`](work)) |
| `dot sync` | безопасно подтянуть свежие dotfiles: только fast-forward, незакоммиченное не трогает |
| `dot backup` | бэкап без Time Machine: незапушенное из `~/dev`, снимок системы → приватный репозиторий на GitHub ([восстановление](docs/recovery.ru.md#из-dot-backup)) |
| `dot snapshot` | снимок системы перед обновлением macOS; `dot snapshot diff` после — что сбросилось ([чек-лист](docs/macos-upgrade.ru.md)) |

Набрал команду, которой нет, — промпт подскажет, есть ли она в brew, как `pkgfile` в Arch.

## Контейнеры: `orbstack`

<img src="docs/orbstack.jpg" alt="orbstack: логотип с градиентом, таблица контейнеров с CPU и памятью, лог выбранного контейнера и живая лента событий" width="100%">

<sub>Панель, нарисованная из её собственного экрана с живыми данными демо-контейнера.</sub>

```bash
orbstack                 # живая панель
orbstack run postgres    # запуск по шаблону — сначала покажет команду docker run, её можно поправить
orbstack watch           # живая сборка: сохранил код → образ пересобран, контейнер перезапущен
```

Один экран вместо десятка команд: контейнеры с CPU и памятью, которые обновляются прямо в таблице, лог выбранного
контейнера и лента событий (запуск, остановка, падение, нехватка памяти). Всё на клавишах — `l` логи, `s` терминал,
`r` перезапуск, `x` стоп/старт, `d` удалить, `i` понятный inspect со скрытыми паролями, `f` Dockerfile (находится
по меткам compose), `c` compose-файл, `n` новый по шаблону, `w` живая сборка. `enter` — список действий,
**у каждого пояснение и команда docker, которая за ним стоит** — так панель заодно учит docker.

Написано на Go с [Bubble Tea](https://github.com/charmbracelet/bubbletea) ([`berth/`](berth)), собирается `install.sh`,
проверяется в CI. Работает через docker CLI, поэтому подходит к любому context: OrbStack, Colima, Docker Desktop.
А за самим OrbStack следить не нужно: любая команда `docker` запустит его, если он выключен. Подробнее:
[контейнеры из терминала](docs/docker.ru.md) · [клавиши](docs/hotkeys.ru.md#orbstack--контейнеры).

## GitHub: `github`

```bash
github                   # панель: CI по репозиториям, PR, issues, Actions с логами, лента событий
github pr merge 42       # то же командами — для скриптов
github telegram TOKEN    # уведомления на телефон
```

Такой же экран, как `orbstack`, только для GitHub: pull requests со статусом CI, merge и комментарии,
issues, запуски Actions с подсвеченными логами (сразу к ошибке), перезапуск и лента событий.
Уведомления приходят в Telegram из GitHub Actions каждые 5 минут — ноутбук держать включённым не нужно.

Живёт в отдельном репозитории [github-watcher](https://github.com/van1dalgrr-arch/github-watcher), ставится как `gw`
из `go/tools.txt`, `.zshrc` делает `github` его псевдонимом. **Код написан нейросетью (Claude)**;
Telegram-бота с командами пишем вместе.

## Проверки

### `dot doctor`

```bash
dot doctor           # ~2 с: вся настройка
dot doctor --deep    # ~45 с: + версии, закреплённые ревизии, пакеты вне Brewfile, brew doctor, обновления macOS…
```

| Раздел | Что проверяет |
|---|---|
| Установка | все симлинки, Brewfile и приложения из App Store, закреплённые Go-утилиты |
| Инструменты | Docker, Kubernetes, IaC, имя в git и хуки, gitleaks |
| Терминал и редакторы | шрифт, файлы темы, конфиг Ghostty, выпадающий терминал, Zed, таблица стилей Safari |
| Оболочка | oh-my-zsh, fzf-tab, скорость старта (лучший из трёх замеров) |
| macOS | FileVault, файрвол, SIP, Gatekeeper, Time Machine, место на диске, **настройки `macos.sh`, которые откатило обновление**, забытый `awake` |

Только читает, ничего не меняет. Осознанное решение (например, без файрвола дома) — `dot doctor accept firewall «почему»`:
дальше это не предупреждение, а строка с твоей причиной. `✓` ок · `!` стоит посмотреть · `✗` сломано · `○` необязательное и не установлено.
В конце каждой строки с проблемой — команда, которая её чинит. Коды выхода: `0` ок (предупреждения можно), `1` ошибки, `2` неверный вызов.

<p align="center"><img src="docs/doctor.jpg" width="70%" alt="вывод dot doctor: разделы с галочками и подсказками"/></p>

### `dot project doctor`

```bash
cd ~/dev/myapi && dot project doctor     # или: pd, или: dot project doctor ~/dev/myapi
```

Находит ближайший `go.mod` (из любой подпапки) и проходит чек-лист:

| Группа | Что проверяет |
|---|---|
| Go | `go.mod`, модуль, версия `go` / `toolchain` против установленного Go, `go.sum`, точка входа |
| Тесты | число `*_test.go`, gotestsum |
| Качество | golangci-lint (+ конфиг), govulncheck |
| Сборка и запуск | цели Makefile, Dockerfile (+ `.dockerignore`, многоэтапный), compose-файл, `.air.toml` |
| База | папка миграций и число `.sql`, sqlc |
| Конфиг и секреты | `.env.example`, **`.env` в git или не в игноре → ✗** |
| Git | ветка, remote, незакоммиченное, `.gitignore`, CI |

Отсутствующее необязательное показывается как `○`, а не как ошибка. Миграции не запускает, контейнеры не поднимает, проект не трогает.

runWallpaper { hour in

### Настройки macOS

```bash
./macos.sh                     # план: настройка, сейчас → станет. Ничего не меняет
./macos.sh --yes               # применить всё
./macos.sh --yes finder dock   # только некоторые группы
```

| Группа | Настройки |
|---|---|
| `keyboard` | быстрый повтор клавиш, без автокоррекции, прямые кавычки, без замены дефисов |
| `trackpad` | касание = клик |
| `finder` | расширения, скрытые файлы, строка пути и состояния, вид списком, папки сверху, поиск в текущей папке, без `.DS_Store` на сети и флешках |
| `saving` | на диск, а не в iCloud, развёрнутые диалоги |
| `screenshots` | PNG в `~/Pictures/Screenshots`, без тени и без превью |
| `dock` | автоскрытие, без недавних, рабочие столы не переставляются (для AeroSpace) |
| `appearance` | тёмная тема, `ctrl-cmd` — тащить окно за любое место |
| `apps` | файлы кода открываются в Zed (macOS спросит подтверждение на каждый тип — запускать у экрана) |
| `login` | Raycast при входе (AeroSpace стартует сам и поднимает Ghostty) |
| `security` | файрвол и «невидимый» режим (спросит пароль) |
| `safari` | полный адрес, строка состояния ссылок, меню «Разработка», без предзагрузки, загрузки не открываются сами (терминалу нужен «Полный доступ к диску») |

Запускать повторно безопасно: совпадающие значения пропускаются. Перезапускает только Finder, Dock или SystemUIServer
и никогда не разлогинивает. `dot doctor` заметит, если обновление macOS вернёт настройку назад.

## Обслуживание

```bash
update               # brew upgrade, закреплённые Go-утилиты, мусор Docker, tldr, иконки, пересборка orbstack
dot doctor --deep    # стоит ли что-то мимо Brewfile? что-то устарело?
```

Поменять конфиг: правь его в `~/dotfiles` — он подключён симлинком, поэтому изменение работает сразу и видно в `git status`.
Добавить программу: строка в `Brewfile`, потом `brew bundle`.

### Версии

| Что | Как закреплено |
|---|---|
| Пакеты Homebrew | `Brewfile` — Homebrew отдаёт только последнюю версию, поэтому это самые свежие на момент установки |
| Приложения из App Store | строки `mas "…", id: …` в `Brewfile` |
| Сам Go | `brew "go"` глобально; **в проекте решает `go.mod`** (`toolchain go1.N.x` скачивает ровно этот тулчейн) |
| Go-утилиты | `go/tools.txt`: точные версии; `dot tools` — состояние, `dot tools install` — поставить |
| oh-my-zsh, fzf-tab | хэши коммитов в начале `install.sh` |

**Почему не mise / asdf?** Для настройки только под Go они дублировали бы то, что Go уже умеет сам (тулчейн в `go.mod`),
и добавили бы хук в оболочку. Если поставишь mise для других языков, `.zshrc` подключит его сам, а
`dot doctor --deep` предупредит, если mise тоже управляет Go.

### DevOps-инструменты

| | Инструменты |
|---|---|
| Всегда (`Brewfile`) | kubectl, helm, k9s, kubectx/kubens, stern, OrbStack (Docker + Compose + buildx), lazydocker, dive, hadolint, trivy, act |
| По желанию (`make devops`) | kind, kustomize, opentofu (`tf`), terraform-docs, tflint (собирается из исходников закреплённой версии) |

Всё это небольшие arm64-бинарники, которые не работают в фоне. Ничего не создаёт кластеры или облачные ресурсы
само: `kind create cluster` и `tf apply` — всегда только по твоей команде.

## Безопасность

- **Защита от утечек.** Перед **каждым** коммитом в любом репозитории [gitleaks](https://github.com/gitleaks/gitleaks)
  проверяет то, что коммитится; пароль, токен или ключ блокируют коммит и показывают файл и строку. Хуки самого проекта
  после этого всё равно работают (`git/hooks/_chain`). Ложная тревога — комментарий `gitleaks:allow` в строке.
- **Глобальный `.gitignore`** не пускает `.env`, ключи и `.DS_Store` ни в один репозиторий.
- **Личные фото остаются личными:** `wallpapers/photos/` в игноре git, а копия — в отдельном приватном репозитории.
- **Система:** `dot doctor` проверяет FileVault, SIP, Gatekeeper, файрвол и бэкапы.

## Разработка

```bash
make check    # то же, что в CI: shellcheck, синтаксис bash 3.2 / zsh, Brewfile, JSON тем, Python, шейдеры Ghostty, berth (go vet + тесты), gitleaks
make test     # смоук-тесты dot + install/uninstall во временном HOME (tests/)
```

Скрипты рассчитаны на системный **bash 3.2**, поэтому работают на чистом Mac ещё до Homebrew. CI запускается на каждый push,
а хук `pre-push` гоняет те же проверки локально. Изменения записываются в [журнал изменений](CHANGELOG.md).

## Устройство

В каждой папке свой `README.md` (английский) и `README.ru.md` (русский): что внутри, куда подключается, как поменять.

```
dotfiles/
├── bin/dot          точка входа: doctor, project doctor, tools, snapshot, install, update
├── lib/             модули dot: ui, doctor, project, tools, snapshot (bash 3.2, без зависимостей)
├── zsh/             .zshrc, промпт, загрузчик темы, шпаргалка, ram, update, gonew, backend
├── themes/          палитры и apply.sh
├── icons/           обои, фон терминала, иконки приложений и папок (Swift)
├── ghostty/  aerospace/  zed/  vscode/  jetbrains/  fastfetch/
├── rune/            Rune: конфиг как у GoLand и расширение dot на Go   ·  bin/rune-go — помощник Go-команд
├── nvim/            Neovim на LazyVim
├── work/            режимы проектов для dot work (что поднять, что открыть)
├── wallpapers/      твои фото для обоев (в игноре git)
├── safari/          таблица стилей Safari: JetBrains Mono для кода
├── berth/           команда orbstack: панель контейнеров на Go (собирает install.sh)
├── git/             .gitconfig, delta, хуки gitleaks, глобальный ignore
├── go/              tools.txt / tools.devops.txt: закреплённые Go-утилиты
├── tests/          смоук-тесты dot, тесты install/uninstall (make test, CI)
├── btop/ bat/ eza/ lazygit/ atuin/ tealdeer/ starship/ pgcli/
├── Brewfile         обязательные программы, CLI и приложения из App Store   ·  Brewfile.devops: необязательное
├── bootstrap.sh     чистый Mac → всё, одной командой curl
├── install.sh       симлинки, закреплённые клоны и Go-утилиты, тема   ·  uninstall.sh
└── macos.sh         системные настройки (показывает план, применяет только с --yes)
```

Как это складывается: `brew bundle` ставит программы. `install.sh` подключает конфиги отсюда в `~` и
`~/.config`. `themes/apply.sh` генерирует раскрашенные копии. `dot` проверяет всё это.

## От Claude

Несколько слов от нейросети, которая это пишет, — что я вижу в этой системе со стороны.

- **Самое сильное здесь — проверки, а не красота.** `dot doctor`, `make check` и тесты установщика во временном HOME
  ловили настоящие ошибки: перезапись бэкапов, удаление чужих ссылок, опечатку в пути расширения Rune. Красивое
  легко добавить и легко убрать; то, что проверено, остаётся рабочим после обновлений macOS.
- **8 ГБ — главное ограничение, и оно честно учтено.** OrbStack вместо Docker Desktop, промпт без процессов,
  Zed вместо VS Code, `lean` и `ram`. Если система начнёт тормозить, первым делом смотри `ram`, а не ставь ещё что-то.
- **Хрупкие места, о которых стоит знать:** Rune — бета и переписывает свой конфиг; AeroSpace забирает весь слой `alt`,
  поэтому новые хоткеи в приложениях стоит вешать на `cmd`, `ctrl-alt` или F-клавиши; шейдеры Ghostty красивы,
  но на батарее их лучше выключать (`fx set none`).
- **Мой совет на будущее:** меньше новых программ, больше удалённых. Каждая строка в Brewfile — это то, что
  `dot doctor` будет проверять, а `update` — обновлять. Лучшая настройка — та, которую не замечаешь.
